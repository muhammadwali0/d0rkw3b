# Public Python API

```python
from d0rkw3b import investigate, providers

plan = investigate("example.com", recipe="domain-footprint")
data = plan.to_dict()
registry = providers()
```

These two package-level functions are supported entry points. They are offline:
no socket calls, browser opening, plugin loading, or implicit persistence.
`providers()` returns validated effective provider dictionaries, including explicit local snapshots/preferences; `providers(bundled=True)` returns only bundled definitions. `investigate()`
returns a structured plan with `entity`, `entities`, `relationships`, `observations`,
`paths`, `diagnostics` and `recipe`. `to_dict()` adds `schema_version: 1` and returns
JSON-compatible data. Invalid input or an incompatible recipe raises ValueError.
Internal module paths are not a compatibility promise.

Options: `type`, `recipe`, `all`, `network` (clearnet/tor/all), `provider_files`,
`recipe_files`, `parameters`, `category` and `pack`. Target parameters cannot override entity identity.
The `created_at` option accepts an explicit timezone-bearing ISO timestamp for
replaying imported runs/tests; omit it for actual current creation time.

Entity IDs derive from type and normalized value; timestamps do not affect them.
Raw input is retained. Domain casing normalizes; usernames retain case because
platforms differ. Email local-part casing is retained. A username and email never
merge based on shared text. Entities initially cover existing query types; broader
entity types will be added only alongside working consumers.

Every relationship records source/method/reference/collection time, observed time,
kind (observed/inferred/manually-added) and qualitative confidence. The only
currently automatically produced relationship is email `uses_domain`, explicitly
identified as **syntax parsing**, without asserting mailbox/domain existence.
Predicates supported by the schema for explicit evidence are `resolves_to`,
`uses_nameserver`, `belongs_to`, `has_profile`, `owns`, `references`, and `has_hash`.
No relationships are guessed from generated profile URLs.

Generated URL observations always use `generated_query`, confidence `unverified`,
and no output entity or relationship. Provenance records template rendering and
that the destination was not contacted. Other observation kinds represent
observed/imported/manually-added evidence; they are not generated by URL rendering.
IDs and ordering are deterministic; actual creation timestamps vary between runs.
The clock option makes full serialized plans reproducible when required.
